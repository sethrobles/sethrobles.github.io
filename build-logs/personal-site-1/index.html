The development of this website over time. The static generator and CMS wiring + potential future changes.

https://sirobles.com/blogs/open-source/This is a sample build log. Build logs are the informal, behind-the-scenes counterpart to a polished project summary — the messy middle, the dead ends, and the decisions made along the way.

So, initially my website was hosted on https://sethrobles.github.io (still redirected here) and it was made for professional reasons. I have since realized that self expression is something that I think I enjoy doing through the website and that I will do.

As a result, I added on the blogs section of the website. But then, I realized it would be nice to have a separation of Projects (which would be a more professional final display of a project), vs build logs which will include the detailing. The two should be linked.

The personal site description is particularly messy because it was not something I thought of as something that I wanted to very rigorously talked about.

Those were my original intentions though, I will now talk about how the website has changed over time.

Initially, I was working out of VSCode with Static Jinja (still in Static Jinja), using templates for each of the different projects/blogs. I would basically create a new markdown file and fill out information related to the blog (date, project name, slug-title, github link, etc.). This was okay for a while, but at some point I realized it would not be that great.

As a result, I decided to add on a CMS (Content Management System) that would help avoid always needing to write code. Basically helped remove some of the boiler plate + ideally would allow me to write these blogs out faster. I added on Decap CMS, which I have been using for a few months.

I also have gone through a few changes in reference to the general look/design. Right now, it's this new beige and teal. Before it was this blue and white that I was told several times by my girlfriend to change and so I did. Like most things, it seems she was right, I like the new website's look much more.

One change that I did when I added on the build logs was that I had them linked to projects. The idea is that a specific build-log and project will share a slug title, since they're inherently going to be related. This might change in the future, but I think right now I like the idea. The thing is, that it's currently possible to save several build logs to one project, but I'm not really sure how/why I would do this. I guess projects have several stages so it makes some sense, but it's not my favorite, I kind of like a long scroll. We'll see if that changes.

One addition I liked was adding my hobbies to the bottom of the first page. The issue is that the strava api recently moved away from being free (I complained about this very briefly here. I think it just is so silly to me when companies do that. Anyways, that's part of the reason that I moved away from Goodreads to Hardcover. They are a young open-source project, but I saw that they were trying to improve upon the openness of Goodreads. I think this is something that should change. If you're giving your data to companies, I personally feel that they should be willing to let you have it back, especially since many of them make money of of it. Regardless, I decided that I would pull the data from these websites regularly using Github Actions. So they run on a somewhat infrequent basis. If I ever decide to host my website and stuff locally, I'll likely just make it a cron job.

July 9th 2026

I'm currently looking into switching CMSes. One think that's been a problem is the fact that I can't easily do Carousel images throughout the text for Decap CMS. Maybe I can, I haven't looked into it a lot, but I've heard that Tina will be something that's a little more easy to set up for different things I want. Right now, I typed out the html tag in markdown in order to get that centering above. It's a little ridiculous for a CMS where the whole point is to move away from markup languages. Anyways, there'll potentially be updates. I'm having Claude loop through an initial design update with Tina and will test that locally then potentially deploy.

I'm looking into this right now and debating. My website is pretty static and I like it. I don't necessarily want a super JS heavy website. What I do want to do is better image storage + holding. Right now, I upload images and I think it's not ideal. I would like them to be actually well stored such that they can load easily despite poor internet connection. I'm also wanting them to be linked with slugs (so that it's easy to port over any pictures from a build log that I might want in a final project).

I think that's all for now, I'm going to work on other stuff but maybe will have an update depending on what I feel about the CMS. I'm also looking into Decap still, there's a chance that I can add the buttons I need, I just didn't look too deep into it orignally.

July 10th 2026

I came back to my computer and decided that I didn't like Decap again. The blocky nature of the CMS just isn't my favorite. So I set up a Tina account and am hoping to be blogging from it by the end of the day. I haven't edited out Decap, but I think I'll likely be sticking with Tina because it's prettier.

I still will need to edit my images structure although I'm not really sure what's possible with Tina. I've realized they take far longer to load than necessary. I'm not really a photographer, so "okay" photos is okay with me. See what I did there :).

I'm also working on switching my Strava api to a garminconnect api. This is mostly just rewriting it. Also, someone told me that just listing my activities is getting kind of boring. So I think a more "stats-like" listing would be interesting. Like different kinds of workouts. Number of workouts in the last 7 days. Miles this year. That kind of thing.

July 12th 2026

So I've realized that I don't really like the TinaCMS that much either just yet. There's some fiddling that needs to happen with things like recreating my current slug setup and while it's prettier, there's differences in how easily I can integrate photos. I'm planning on revamping my photo set up so that I upload whatever here and they get transformed to a lighter format so that they render easily on the web. I haven't figured it out really yet, but I think I should consider this more before I swap to TinaCMS.

Regardless, I have swapped from the Strava api. It now pulls directly from my garmin, but it still links to my strava since that's where I'm more likely to interact with other people.

I think I'm probably going to take a small break from editing the formatting of my website. I recently made small adjustments to my resume after some prompting from Ava and I think this in general has got me feeling a little tired of looking at my computer / setting up coding loops.

Yeah, hopefully I'm sticking to writing about other things as opposed to updating this for a while. Honestly, I like Decap but it's just a little blocky. I think that I was too hasty jumping onto Tina. I have the TinaCMS dashboard set up, but I just really don't like it's look, so I'm avoiding it for a while.
